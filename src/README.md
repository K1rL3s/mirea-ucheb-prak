# Процедурная реализация: завершение аренды автомобиля

Программа автоматизирует четыре операции процесса «Оформление и проведение поминутной аренды автомобиля»:

| Операция (задача на BPMN-диаграмме) | Функция |
|---|---|
| Проверить комплектность фотоосмотра | `check_inspection()` |
| Проверить место завершения аренды | `check_finish_zone()` |
| Рассчитать стоимость поездки | `calc_trip_cost()` |
| Изменить статус автомобиля | `set_car_status()` |

Для каждой аренды из `data.json` программа определяет зону завершения, рассчитывает стоимость с доплатами, проверяет фотоосмотр при сдаче и переводит автомобиль в статус «свободен» или «на обслуживании»

## Запуск

Python 3.11 или новее (разработка велась на 3.14), внешних зависимостей нет. В Linux и macOS вместо `python` может понадобиться `python3`

```sh
cd src
python main.py
```

Другой файл данных той же структуры передаётся аргументом: `python main.py путь/к/data.json`

## Файлы

- `operations.py` - функции операций
- `main.py` - загрузка данных и сценарий завершения аренды
- `data.json` - тестовые данные: по списку записей на каждую сущность логической модели (`client`, `tariff`, `car`, `zone`, `zone_point`, `booking`, `rental`, `rental_segment`, `inspection`, `photo_view`, `photo`, `surcharge_type`, `surcharge`, `payment`, `claim`)
- `test_operations.py` - тесты; программе внешние библиотеки не нужны, тестам нужен pytest из `requirements.txt`: `pip install -r requirements.txt`, затем `python -m pytest` в каталоге `src`

## Правила и границы прототипа

Граница многоугольника включается в зону завершения; при пересечении зон выбирается первая в `data.json`. Зоны должны быть простыми многоугольниками не менее чем из трёх вершин, координаты - конечными числами. Время сегмента не может быть отрицательным, допустимы только режимы «движение» и «ожидание». Каждый сегмент округляется вверх до целой минуты отдельно. Ставки и доплаты задаются неотрицательными строками с двумя десятичными знаками; расчёт ведётся по переданному тарифу

Если фотоосмотр при сдаче отсутствует, все обязательные ракурсы считаются недостающими, а автомобиль направляется на обслуживание. Проверяется наличие ракурсов, содержимое снимков оценивает сотрудник

Программа показывает расчёт и новый статус в консоли. Исходный JSON не перезаписывается; вызовы банка, бронирование, обслуживание и претензии не имитируются. Ключи записей и ссылки между сущностями должны соответствовать логической модели
